# Smart Profile

**Умный кредитный кабинет предпринимателя** — веб-кабинет, в котором владелец малого бизнеса выбирает кредитный продукт, подаёт заявку и видит, как прошла автоматическая проверка и почему.

Главная идея — понятный результат. Вместо сухого «отказано» пользователь видит, какая проверка не пройдена (кредитная история или реестр компаний) и по каким причинам.

## Возможности

- Регистрация и вход, JWT хранится в `httpOnly`-cookie
- Публичный каталог кредитных продуктов с пагинацией
- Одна компания на пользователя, режимы просмотра и редактирования
- Заявка на кредит: сумма и срок проверяются по лимитам продукта
- Автоматическая проверка в два шага: кредитная история (БКИ), затем реестр компаний (ЕГРЮЛ)
- Результат проверки с статусом каждого шага и понятными причинами
- Дорожная карта на главной: аккаунт → компания → заявка → проверка, с отметкой, где сейчас пользователь
- История заявок в профиле; три последние заявки на главной
- Роли: `CLIENT` (по умолчанию), `MANAGER` и `ADMIN` создают продукты и видят все заявки

## Быстрый старт

### Требования

- JDK 21 или новее
- Node.js `^22.18.0` или `>=24.12.0`

### Бэкенд

1. Создайте или отредактируйте `backend/smart-profile/src/main/resources/application.properties`:

   ```properties
   # H2 в памяти: данные стираются при каждом перезапуске.
   # Для постоянного хранения: jdbc:h2:file:./data/smartprofile
   spring.datasource.url=jdbc:h2:mem:smartprofile
   spring.jpa.hibernate.ddl-auto=validate
   spring.flyway.enabled=true

   # секрет в base64, не короче 32 байт. Сгенерировать: openssl rand -base64 32
   jwt.token=CHANGE_ME_BASE64_SECRET
   # время жизни токена в миллисекундах (3600000 = 1 час)
   jwt.access-exp=3600000
   ```

2. Запустите:

   ```bash
   cd backend/smart-profile
   ./mvnw spring-boot:run
   ```

   API доступен по адресу `http://localhost:8080/api`. При старте Flyway создаёт схему и добавляет кредитные продукты. В логе должна появиться строка `Successfully applied ... migration`.

### Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`. Адрес API задан в `src/api/api.ts`, клиент работает с `withCredentials: true`, поэтому CORS на бэкенде должен разрешать этот origin.

## API

Все пути начинаются с `/api`. Все эндпоинты, кроме публичных, требуют cookie авторизации.

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/auth/register` | публичный | Создать аккаунт `CLIENT` (`email`, `password`, минимум 6 символов) |
| POST | `/auth/login` | публичный | Устанавливает cookie `accessToken` |
| POST | `/auth/logout` | публичный | Удаляет cookie |
| GET | `/users/me` | пользователь | Текущий пользователь (`email`, `phone`) |
| GET | `/credit-products` | публичный | Продукты с пагинацией |
| GET | `/credit-products/{id}` | публичный | Один продукт |
| POST | `/credit-products/create` | `ADMIN`, `MANAGER` | Создать продукт |
| POST | `/companies/create` | пользователь | Создать компанию пользователя |
| GET | `/companies/my-company` | пользователь | Компания пользователя или `204`, если её нет |
| PUT | `/companies/change` | пользователь | Изменить компанию пользователя |
| POST | `/applications` | пользователь | Подать заявку и запустить проверку |
| GET | `/applications/my-history` | пользователь | Заявки пользователя, сначала новые |
| GET | `/applications` | `ADMIN`, `MANAGER` | Все заявки |
| GET | `/swagger-ui.html` | публичный | |

Эндпоинты с пагинацией принимают параметры `page`, `size` и `sort`.

### Как проходит заявка

1. Пользователь создаёт компанию (ИНН, ОГРН, адрес, выручка).
2. Отправляет `POST /applications` с `creditProductId`, `amount` и `termMonths`.
3. Сервис проверяет сумму и срок по лимитам продукта.
4. `VerificationService` запускает проверку БКИ; проверка ЕГРЮЛ выполняется только если БКИ пройдена.
5. Заявка сохраняется вместе с результатом проверки и причинами.

## Проверка (mock)

Обе проверки сейчас заглушки, написанные так, чтобы их можно было заменить реальными интеграциями.

- **БКИ (кредитная история):** не пройдена, если запрошенная сумма больше половины годовой выручки компании.
- **ЕГРЮЛ (реестр компаний):** проверяет контрольные цифры ИНН и ОГРН. Реальный реестр не вызывается.
- Если БКИ не пройдена, ЕГРЮЛ записывается как «не проверялась».

Чтобы увидеть успешную заявку, возьмите ИНН `7707083893`, ОГРН `1027700132195`, выручку `1000000` и подайте заявку на `400000`. Заявка на `600000` покажет отказ с причиной.

## База данных и миграции

Изменения схемы лежат в `backend/smart-profile/src/main/resources/db/migration` и выполняются через Flyway.

- Называйте файлы `V<номер>__<описание>.sql` (заглавная `V`, два подчёркивания, без пробелов).
- Никогда не редактируйте миграцию, которая уже выполнялась на постоянной базе. Добавьте новый файл.
- Hibernate работает в режиме `validate`: он сверяет сущности с миграциями при старте и сам схему не меняет.
- Для ролей, кроме `CLIENT`, интерфейса нет. Измените колонку `role` в таблице `users` на `MANAGER` или `ADMIN` вручную.

## Известные ограничения
- Cookie авторизации не помечена как `Secure`, а CORS разрешает только `localhost:5173`. Для продакшена оба параметра нужно изменить.
- Некоторые контроллеры возвращают текст исключений и ошибку 500 для отладки. Перед развёртыванием замените их на `@RestControllerAdvice`.
- Нет загрузки документов, шага подписания договора и тестов.
